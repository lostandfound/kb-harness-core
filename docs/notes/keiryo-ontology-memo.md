# 考察メモ: AI にオントロジーは必要か、軽量オントロジーの要点はどこか

2026-09-25 のディスカッションの記録。ハーネスの設計方針（語彙を小さく保つ理由）を考えるためのメモで、例は導入先の一つ omnibus-kb（`lostandfound/omnibus-kb`）から取っている。本文中の「この KB」はそれを指す。

きっかけは HELLO_CYBERNETICS「AIにオントロジーは必要か？」（Zenn、2026-09-26、https://zenn.dev/cybernetics/articles/a3f4adf33265ce ）。記事の主張は、AI が社内データを探索するのに形式オントロジーやナレッジグラフは必須ではなく、設計された RDB とセマンティックレイヤーがあれば多くの関係は JOIN で取り出せる、形式オントロジーが効くのは推論規則を共有したいときで、まず誤答を分析し原因に応じて対策を選べ、というもの。

## タイトルへの回答

推論機付きの形式オントロジーは、たいてい要らない。しかし、用語・階層・関係を明示的に固定する仕事は消えない。それをセマンティックレイヤーと呼ぶか軽量オントロジーと呼ぶかは、置き場所の違いにすぎない。

記事への同意点と留保は次のとおり。

- 記事の最も強い主張は「オントロジーが解く問題の大半は、セマンティックレイヤーが解いている」。指標や結合を一度定義し、エージェントは定義を選ぶだけにする。Business Objects のユニバース（1991）がやろうとしたことの消費者が、人間から LLM に変わった。
- 記事は「オントロジー」を OWL の公理と推論機に狭く取っている。表と列を決めること、指標の定義を書くこと自体が軽量なオントロジーの仕事であり、記事は形式オントロジーを退けつつ、その中身の大半をセマンティックレイヤーと呼び直して採用している。
- 記事の例は「一組織の、構造が決まったデータ」に偏る。JOIN で答えられるのは表記が揃っている前提があるからで、「PE／ポリエチレン／LDPE」の揺れと「LDPE はポリエチレンの一種」を誰も表に書いていない状況は、複数機関に限らず社内でも起きる。
- LLM が関係の下書きを大量に作れるようになり、形式化のコストは下がった。記事の「不要」論はコストが高かった時代の前提に乗っている面がある。
- セマンティックレイヤーは「集計の意味」を固定するのは得意だが、「概念どうしの関係」（例: 香取海は利根川東遷によって縮小した）は指標の形をしていない。記事の二分法（RDB+セマンティックレイヤー か 形式オントロジー か）の間に、実務で最も使われる中間帯がある。それがこの KB のような軽量オントロジー。

## 軽量オントロジーは何を捨て、何を残しているか

この KB の `knowledge/vocabulary.yml` を実物として見る。型は 7、述語は 4（`related-to` / `part-of` / `created-by` / `derived-from`）。

残しているもの

- 型と、述語の domain / range。「Dish は Person に part-of できない」を `kb validate` が弾く。推論機の代わりに検証器がある。
- 方向。エッジは一方向のみ。逆向きを推論で導くためではなく、二重に書くと矛盾が生まれるから。
- 確度。`confidence: C` と Claim。OWL には「たぶん」がない。

捨てているもの

- 推移律。A part-of B、B part-of C から A part-of C は導かれない。
- 述語の意味論。`related-to` は「何か関係がある」以上を言わない。関係の意味は本文にある。

軽量が実務で勝つ理由は、意味の大半を本文に置き、グラフには検証可能な最小限だけを載せる分業にある。推論は LLM が本文を読んで行い、グラフは「どこを読むか」と「型として矛盾していないか」だけを保証する。形式オントロジーはこの分業を拒んで意味をすべてグラフ側に持とうとしたため重くなり、LLM が読める本文との二重管理になった。失ったのは推論、得たのは維持できること。維持できないオントロジーは存在しないのと同じなので、この交換は割に合う。

## 足りなくなる場面

- `related-to` の肥大。関係の種類を増やさないとグラフがリンク集になる。しかし述語を増やすほど形式オントロジーに近づき、維持コストが上がる。「人が覚えていられる述語の数」が軽量の実際の上限。感覚では 10 前後。
- 推移律が欲しくなる瞬間。「中国料理に属する料理を全部出して」のように 2 段の `part-of` を辿る質問が RAG に来たとき。ただし OWL を入れる必要はなく、ハーネス側に 2 段までの `part-of` を辿る機能を足せば済む。推論は「オントロジーの機能」ではなく「ハーネスの機能」として持つのが軽量路線の自然な延長。

## 「軽量」の要点はどこか

論点は、軽量の本質が「述語の少なさ」か「確度を一級市民として持てること」か。

結論（オーナーの立場）: **述語の少なさ**。語彙が小さいことが、覚えられる・検証できる・本文に意味を委ねられる、の三つを同時に成り立たせる。Claim と確度は有用だが、それは述語が少ないからこそ成り立つ付属物であり、本質ではない。

この判断から導かれる方針

- 述語は安易に増やさない。増やす前に、既存の述語と本文の書き方で表せないかを検討する（review-entity-model スキルの役割）。
- `related-to` の氾濫は述語の追加ではなく、本文の「関連項目」で関係の意味を一文添えることで受け止める。
- 推論が必要になったら語彙ではなくハーネス（`kb` の機能）に足す。
