# 導入先のローカルスキルとの共存のメモ

## 観察した問題

導入先 KB が自前のスキルを持つとき、`apm install` がそれを上書きしないか、という懸念があった（Issue #50）。ハーネスのスキル名は `add-entity` / `ask-kb` など一般的な語で、導入先が同名を付ける可能性がある。`docs/integration.md` に共存の指針が無い。

apm-cli 0.33.0 を一時ディレクトリで実測した。

| 状況 | 結果 |
|---|---|
| 配置先に手で置いた同名スキルがある | 依存側は展開されず、ローカルが残る。診断に `1 file skipped -- local files exist, not managed by APM` と `Use 'apm install --force' to overwrite` が出る |
| 導入先の `.apm/skills/` に同名スキルがある | 依存側を置き換えてローカルが展開される。診断は `1 skill replaced by a different package (last installed wins)` |

公式の install リファレンスも、`--force` は「ローカルで書いたファイルを衝突時に上書きする」と書き、`.apm/` のローカルが衝突で勝つと書く。

## 検討した対応

1. **文書に指針を書く（採用）**: 契約の正本 `docs/integration.md` に、ローカルのスキルの置き場所・命名・`--force` を使わない運用を書く。
2. **`kb doctor` で同名衝突を警告する（見送り）**: 配置先ディレクトリの名前が `--target` で変わり、ハーネスは配置先のパスを持たない（AGENTS.md「ランタイム非依存」）。`apm.lock.yaml` の `deployed_files` に載らない同名ファイルを検出する案はあるが、実害の報告がまだ無い。
3. **ハーネスのスキル名に接頭辞を付ける（見送り）**: 既存の導入先の参照とスキル名が壊れる。

## 判断

文書だけを直す。ハーネス側のコードは変えない。

- ローカル専用のスキルは導入先の `.apm/skills/` に置く。配置先は生成物であり直接編集しない。
- ローカルのスキル名には KB 固有の接頭辞を付け、ハーネスのスキル名と衝突させない。
- ハーネスのスキルを差し替えたいときは同名をローカルに置けるが、版を上げても追従しない。別名の補助スキルで包む方を勧める。
- `apm install --force` は使わない。

## 未決事項

- `kb doctor` で同名衝突を警告するか。再開条件: 導入先で同名の取り違えが実際に起きたとき。
- 版更新時にローカルが勝った同名スキルへ追従する手段（差分の通知など）。

## 実装の記録
